digitalis/scripts/summarize-benchmarks.py digitalis/out/bench/<stamp>.ndjson \

The fastest reliable JIT tier per row is **bold**. Cells marked ⚠ exceeded a
10% relative interquartile range and must not be quoted; the best-vs-interp
column uses only reliable cells (falling back to the reliable tier when the
faster one is noisy). See `docs/benchmarking.md` for the methodology.

**native** is the same workload built for x86_64 and run with no translation
in the path — the denominator that says whether translated code is fast enough
to use, which a speedup over the interpreter cannot. It is not a translation
tier, so it is never bolded and never counts toward best-vs-interp. A `—`
means no native baseline exists for that module: the NEON/BF16 probes compute
with ARM64 intrinsics, so an x86_64 build would be a different program rather
than the same work, and a few library modules carry their natives inside
arm64-only artifacts. `run-benchmarks.sh --build-native` builds the rest.
